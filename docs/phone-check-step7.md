# スマホ確認の手順（STEP 7：zip のバックアップと復元）

確認用 URL：https://feature-field-mode.shrine-checklist.pages.dev （バージョン 2.0.0-dev.7）

- **始める前に、STEP 7 が push されていることが必要です**（一覧のいちばん下が 2.0.0-dev.7 になっていること）。
- この確認用 URL には、**実際の現地記録**が入っていることがあります。この手順で消したり上書きしたりするのは、手順 C で作る**テスト用の記録「テストZ」だけ**です。ほかの記録は消さないでください。
- 所要時間は約30分です。Android で全部を行い、iPhone があれば ★ の手順も行います。

---

## 0. 準備（まず今の記録を守る）

1. スマホの Chrome で確認用 URL を開き、アドレスバー右の「⋮」→ 再読み込み（ぐるっと回る矢印）を押す。
2. 一覧画面のいちばん下を見る。
   - **期待**：「バージョン 2.0.0-dev.7」の横に「テスト版」。dev.6 のままなら、もう一度再読み込みする（それでも dev.6 なら、まだ push されていない）。
3. **念のため、今の記録を JSON で残す**：「全データ書き出し」を押して保存する（文字の記録の控え）。
   - **期待**：Android はダウンロードされる。「最後の書き出し（JSON）：（今の日時）」に変わる。

## A. 一覧画面の表示（7-4）

4. 「データの保管」の下を見る。
   - **期待**：「全件をzipで書き出し」「zipから復元」のボタンがある。
   - **期待**：「JSON には文字の記録だけが入ります。写真・録音・メモまで残すときは zip で書き出してください。」の一文がある。
   - **期待**：「まだ全件の zip でバックアップしたことがありません」と「最後の書き出し（JSON）：…」が出る。

## B. 全件の zip で、今の記録を丸ごと守る（7-2・7-4）

5. 「**全件をzipで書き出し**」を押す。
   - **期待**：「写真・録音を読み込んでいます… 1 / N」→「zip を作っています… ○%」→「zip ができました（shrine-backup_日付-時刻.zip・○件・○MB）。『共有／保存』を押してください。」
   - 件数は一覧の記録の数と同じ。位置を記録した記録があれば、赤い字で「この zip には位置情報（参拝した場所の緯度・経度）が含まれます…」も出る。
   - 写真・録音の合計が200MBを超えていると、作る前に「神社ごとに書き出すのがおすすめです…このまま全件の zip を作りますか？」と聞かれる。その場合は「OK」で続けてよい。
6. 「**共有／保存**」を押す。
   - **期待（Android）**：共有画面は出ずに、「…をダウンロードしました（端末の「ダウンロード」に入ります）。」と出る（Android の Chrome は zip を共有できないため）。
   - ★**期待（iPhone）**：共有画面が出る。「"ファイル"に保存」で保存すると「…を共有しました」と出る。
7. 一覧の下を見る。
   - **期待**：「最後のバックアップ（全件の zip）：（今の日時）」に変わる。
8. **この zip は、確認が終わるまで消さずに取っておく**（今の記録の控えになる）。

## C. テスト用の記録を作る

9. 「現地モードを始める」を押す。「前回の下書きを続けています」と出たら「新しく始める」。
10. 神社名に「**テストZ**」と入れる。
11. 写真を2枚撮る。1枚目は撮影直後のラベルで「**鳥居**」、2枚目はラベルなし。
12. 録音を5秒、メモ（「zip のテスト」）を1件残して、「← 閉じる」。
13. 一覧で「テストZ」を見る。
    - **期待**：「下書き」「写真2・音声1・メモ1」のバッジ。

## D. 1神社の zip を作って送る（7-1）

14. 「テストZ」を開き、上のボタン列の「**zipを作成**」を押す。
    - **期待**：「zip ができました（20261101_テストZ.zip・○MB）。『共有／保存』を押してください。」
    - 位置が取れていれば、赤い字で位置情報の一言が出る。
15. 「**共有／保存**」を押す。
    - **期待（Android）**：「20261101_テストZ.zip をダウンロードしました…」。
    - ★**期待（iPhone）**：共有画面が出る。LINE を選ぶと送る相手を選べる。または「"ファイル"に保存」。
16. **Android：ファイルアプリから LINE へ送る**
    - 「Files」（Files by Google）などのファイルアプリを開き、「ダウンロード」に `20261101_テストZ.zip` があることを確かめる。
    - そのファイルを長押し →「共有」→ LINE を選ぶ（自分だけのトークや Keep メモへ送ると安全）。
    - **期待**：LINE に zip が送られる。
17. 一覧に戻る。
    - **期待**：「最後のバックアップ」は手順7のまま（1神社の zip は数えない）。

## E. PC で zip の中身を見る

18. 手順16で LINE に送った zip（または手順15・16のファイル）を PC で受け取り、**リポジトリのフォルダの外**（「ダウンロード」など）に保存して開く。
    - **期待**：`manifest.json`・`visit.json`・`memo.txt`・`photos`・`audio` がある。日本語のファイル名が文字化けしていない。
19. `photos` の写真を開く。
    - **期待**：`01_鳥居.jpg`・`02.jpg` があり、普通に見える。
20. `audio` の録音を Chrome にドラッグするか VLC で開く。
    - **期待**：録った音が鳴る（Android は `.webm`、iPhone は `.m4a` などになる）。
21. `memo.txt`・`manifest.json`・`visit.json` をメモ帳で開く。
    - **期待**：`memo.txt` に「【メモ1】…」と「zip のテスト」がある。
    - **期待**：`manifest.json` に `"kind": "visit"` と、`"appVersion": "2.0.0-dev.7"` がある。
    - **期待**：`visit.json` に「テストZ」と `"label": "torii"` がある。

## F. 削除して zip から戻す（7-3）

22. スマホで「テストZ」を開き、「この神社を削除」を押す。**テストZ であることを確かめてから**「OK」。
    - **期待**：確認に「写真2枚・録音1本・メモ1件も削除されます」と出て、一覧から消える。
23. 一覧の「**zipから復元**」を押し、`20261101_テストZ.zip` を選ぶ。
    - Android：ファイルの選び方で「ダウンロード」を開いて選ぶ。★iPhone：「ファイル」から選ぶ。
    - **期待**：「zip の記録：1件 / 新規 1件・重複 0件 / 復元しますか？」
24. 「**復元する**」を押す。
    - **期待**：「写真・録音を復元しています… 1 / 3」→「復元しました：新規1件。（復元前の状態は診断画面のバックアップ一覧に残っています）」。
    - **期待**：一覧に「テストZ」が戻り、「写真2・音声1・メモ1」のバッジがある。
25. 「テストZ」を開く。
    - **期待**：「現地モードの記録」欄に写真2枚の**サムネイル**（鳥居／ラベルなし）、録音、メモがある。
    - **期待**：写真を押すと全画面で見える。録音の「▶ 再生」で鳴る。撮影チェックの「鳥居」にチェックが付いている。

## G. 同じ zip をもう一度（重複の確認）

26. 一覧で、もう一度「zipから復元」→ `20261101_テストZ.zip` を選ぶ。
    - **期待**：「新規 0件・重複 1件」と、「スキップ（今の記録を残す）」「上書き（zip の内容にする）」「やめる」の3つのボタン。
27. 「**スキップ**」を押す。
    - **期待**：「新しく足す記録はありませんでした（重複はスキップしました）。何も変更していません。」
28. 「テストZ」を開いて現地モードを始め（続きから再開される）、写真を1枚足して閉じる。
29. もう一度「zipから復元」→ `20261101_テストZ.zip` を選ぶ。
    - **期待**：「この端末にだけある写真・録音・メモ1件は消えます。」と出る。
30. 「**上書き**」を押す。
    - **期待**：「復元しました：新規0件・上書き1件」。「テストZ」の写真は2枚に戻る（足した1枚は消える）。

## H. 全件の zip で戻す（スキップだけ）

31. 「テストZ」を削除する（手順22と同じ。**テストZ であることを確かめる**）。
32. 「zipから復元」で、**手順5〜6の全件の zip**（shrine-backup_….zip）を選ぶ。
    - **期待**：今ある記録はすべて「重複」、新規は 0件（テストZ は手順5の後に作ったので、この zip には入っていない）。
33. **必ず「スキップ」を押す**（「上書き」は押さない。今の現地記録が zip の時点に戻ってしまうため）。
    - **期待**：「新しく足す記録はありませんでした…何も変更していません。」

## I. 後片付け

34. 一覧で、記録の数と名前が手順5の前と同じであることを確かめる（テストZ は手順31で消してある）。
35. 「診断」を開く。
    - **期待**：「最後のバックアップ（全件の zip）」が手順6の日時。バックアップ一覧に、復元の前に取ったものがある。「どの記録にも属さないメディア」は 0件。
36. スマホと PC の `20261101_テストZ.zip` は消してよい。**全件の zip（手順5）は、今の記録の控えとして残しておく**（LINE の Keep やファイルアプリなどへ）。

---

## スマホでは確かめないもの

- 30日の知らせ（30日待てないため）。PC で日時を古くして確認済み、境目は自動テスト（`tests/backup-status.test.mjs`）で確認済み。
- オフラインでの zip 作成。STEP 8 で zip の部品を事前に保存するまでは、zip を作るときに通信が必要。

## うまくいかなかったとき

手順の番号と、画面に出た文をそのまま控える。診断画面の「診断内容をコピー」で貼り付けると原因を探しやすい。**途中で記録が消えたように見えたら、それ以上操作せず**、手順5〜6の全件の zip と手順3の JSON を残したまま知らせる（「zipから復元」で「スキップ」を選べば、消えた記録だけが戻る）。
